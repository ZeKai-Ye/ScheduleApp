# AI 对话功能

主界面点「AI 对话」（快捷键 **Ctrl + K**）就能和本地大模型聊天，并且**它真的能替你操作日程**：
查今天有什么、新建一条、改期、标记完成、删掉某一次、切换主题等，都会立刻反映到主界面。

模型跑在**你自己的电脑上**（默认 Ollama + `qwen3:8b`），断网也能用，日程数据不会被发到任何云端。

---

## 1. 五分钟跑起来

1. 安装 [Ollama](https://ollama.com)（Windows 安装包，装完常驻托盘）。
2. 下载模型（约 5 GB，只需一次）：

   ```powershell
   ollama pull qwen3:8b
   ```

3. 打开「日程助手 → 设置 → AI 助手」，确认：

   | 项 | 默认值 |
   | --- | --- |
   | 服务地址 | `http://127.0.0.1:11434/v1` |
   | 接口协议 | 自动判断（11434 → Ollama 原生） |
   | 模型 | `qwen3:8b` |

   点「测试连接」，看到「连接成功…共 N 个模型」即可。

4. 回到主界面点「AI 对话」，直接说话：

   - 今天有什么日程？
   - 明天下午三点加一个「客户沟通」，提前 30 分钟提醒我
   - 把明天的例会改到 16:00
   - 这周的周会都标成已完成
   - 换成夜间主题

> 不需要 AI 的日程功能也可以完全不用它：没打开对话窗口时，软件不会访问任何模型服务。

---

## 2. 选择模型

软件支持两类本地服务，都在「设置 → AI 助手」里配：

| 服务 | 服务地址 | 协议 |
| --- | --- | --- |
| **Ollama**（推荐） | `http://127.0.0.1:11434/v1` | 自动 → Ollama 原生 `/api/chat` |
| LM Studio | `http://127.0.0.1:1234/v1` | 自动 → OpenAI 兼容 `/v1/chat/completions` |
| llama.cpp / vLLM / 中转 | 各自地址 | OpenAI 兼容 |

- **模型选择**有两处：设置页的「获取模型列表」（一次拉全，可下拉选），以及**对话窗口顶部的模型下拉**（随时切换，立即生效并记住为默认）。
- 也可以直接手输模型名（例如 `qwen3:14b`、`qwen2.5:7b`、`glm4:9b`）。

### 为什么默认走 Ollama 原生协议

Qwen3 这类"思考模型"默认会先生成一大段思维链再回答。实测同一句问话（qwen3:8b，关闭思考）：

| 协议 | 关闭思考的做法 | 耗时 | 思维链 |
| --- | --- | --- | --- |
| Ollama 原生 `/api/chat` | `think:false` | **约 1.5 ~ 10 秒** | **0 字** |
| OpenAI 兼容 `/v1/chat/completions` | `reasoning_effort:"none"` | 约 6 秒 | **0 字** |
| OpenAI 兼容（只写 `/no_think`） | 提示词软开关 | 19 ~ 30 秒 | 仍有几百字 |

所以默认「自动判断」：地址是 `11434` 就走原生接口，其它走 OpenAI 兼容。两种协议都完整支持工具调用，
实在想强制指定，就在设置里改「接口协议」。

### 思考等级（默认最低档）

「设置 → AI 助手 → 思考等级」默认 **最低：完全不思考**。这是本地模型最有效的提速手段，
实测 qwen3:8b 同一句问话：

| 等级 | 传到模型 | 耗时 | 思维链 |
| --- | --- | --- | --- |
| **最低（默认）** | `think:false` / `reasoning_effort:"none"` | **6 ~ 10 秒** | **0 字** |
| 低 | `think:"low"` | 42 ~ 52 秒 | 500 ~ 700 字 |
| 中 | `think:"medium"` | 51 秒 | 671 字 |
| 高 | `think:"high"` | 更慢 | 更多 |

> 注意：「低」并不是"比最低再低一点"，而是**打开了少量思考**——比关闭慢 5 倍以上。
> 需要模型做复杂推理（例如"把这周的安排按优先级重排并给建议"）时再往上调。

## 3. 它到底能做什么（工具清单）

AI 不是"假装改日程"——它调用的是下面这些工具，执行完再把结果回填给模型组织成回复：

| 工具 | 作用 | 关键参数 |
| --- | --- | --- |
| `list_items` | 按日期 / 时间段 / 分类 / 关键词查日程 | `date`（今天 / 明天 / 2026-09-15）、`from`、`to`、`category`、`keyword`、`limit` |
| `create_item` | 新建日程 | `title`、`start`（必填）、`end`、`category`、`notes`、`reminderOffsets`、`voiceText`、`allDay` |
| `update_item` | 改标题 / 时间 / 分类 / 备注 / 提醒档位 / 状态 | `id` + 要改的字段 |
| `reschedule_item` | 改期（只动时间） | `id`、`newStart`、`newEnd` |
| `delete_item` | 删除 | `id` |
| `set_status` | 标记待办 / 已完成 / 已取消 | `id`、`status` |
| `next_reminders` | 接下来会响的提醒 | `count` |
| `app_info` | 数据目录、总条数、今天几条、当前主题、版本 | — |
| `set_theme` | 切换浅色 / 夜间 / 跟随系统 | `theme` |

几个设计上的讲究：

- **`#1` / `#2` 编号**：每次查询后会重新编号，模型只需要回传 `#2`，不必抄一长串 GUID
  （本地 8B 模型抄 GUID 很容易抄错）。编号只在当前对话里有效。
- **重复日程只改这一次**：查询会把系列展开成"某一天那一次"，模型用那个 `#N` 改期 / 删除时写入的是
  「仅这一次」例外，其它发生不受影响。
- **时间写法很宽容**：`2026-09-15 15:00`、`明天15:00`、`下周三 上午10点`、`3天后` 都能解析。
- **参数错了不会崩**：工具参数不合法时返回 `{"error":"..."}` 让模型自己纠正，最多允许 4 轮工具往返。

## 4. 命令行（无界面验证 / 脚本）

```powershell
# 列出模型服务上的模型
ScheduleApp.exe --ai-models

# 跟 AI 说一句，打印回复与它调用的工具
ScheduleApp.exe --ai-chat "明天下午三点加一个客户沟通，提前30分钟提醒"
```

两者都支持 `--data <目录>` 指定数据目录、`--out <文件>` 把输出写进文件（方便脚本收集）。
无界面 AI 用的是同一套工具实现，因此可以用来在改代码后快速回归。

## 5. 可调参数

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| 温度 | 0.2 | 工具调用建议 0 ~ 0.3；越高越"活泼"但更容易调错参数 |
| 超时（秒） | 180 | 本地大模型首次加载慢，可以调大 |
| 上下文条数 | 16 | 每次请求携带的历史消息上限，超出从最早开始丢弃（不会拆散"工具调用 + 工具结果"） |
| 最大输出 token | 0 | 0 = 交给服务端默认 |
| 思考等级 | 最低（关闭） | 本地小模型基本不需要思考；等级越低越快、越省上下文（见上文实测） |
| 显示工具调用详情 | 开 | 对话气泡里可展开看 ai 传了什么参数、拿到什么结果 |
| 记入日志 | 开 | 每次写入都会在 `logs` 里留一行，便于回溯 |
| 自定义系统提示 | 空 | 留空用内置（含"必须调用工具""删除前确认""24 小时制"等规则） |

## 6. 排错

| 现象 | 处理 |
| --- | --- |
| 连接失败 / 连不上 | 确认 Ollama 在跑（托盘图标），地址是 `http://127.0.0.1:11434/v1` |
| 模型不存在（404 model not found） | `ollama pull qwen3:8b`；或点「获取模型列表」看实际有哪些 |
| 第一次特别慢 | 模型要从磁盘加载（几 GB），第二次开始就快了；也可调大超时 |
| 一直不调用工具、只是聊天 | 换更大的模型（`qwen3:14b`）或把温度调到 0；内置提示已要求"要动日程必须调用工具" |
| 想换别的本地服务 | 设置里改服务地址 + 协议即可，例如 LM Studio 的 `http://127.0.0.1:1234/v1` |

---

## 7. 已知限制

- **不做流式输出**：等待期间窗口会显示「正在请求模型…（已等待 N 秒）」与当前阶段，可以随时点「停止」。
- 工具覆盖的是**基础交互**：增删改查、改期、状态、提醒查询、主题切换。批量复杂操作（例如"把所有周五的会都挪到下周"）需要多轮对话完成。
- 会话历史与 `#N` 编号只存在内存里，关掉对话窗口（或清空对话）就没了；日程本身当然照常保存。
- 模型的能力决定体验：8B 级别的本地模型偶尔会理解错日期或选错 `#N`，此时它会收到错误信息并重试；
  涉及删除这类不可逆操作时，请确认它复述的目标是否正确。
